## Definition of Done (§78)

After these rules, a tens-of-EXP project should show:

```text
STORY     紧凑、随证据演化（不是任务日志）
STATE     当前科学游标（目标 ≤ 40 行，无新字段）
EXPERIMENTS 持续增长，但每个新增 EXP 对应真实科学问题
DISCOVERY 持续积累方法为什么变化
W2–W3–W4  默认高速方法优化循环
W1        只在真正需要重构方法/问题时进入
```

Not: more experiments → more engineering checklists → more Reviews →
longer STATE → Agent loses the core method.

## Metrics-not-token (§74–75)

Do **not** score token drop or review-count drop. Score:

| Axis | Pass when |
|------|-----------|
| Scientific Focus | Most next actions in 5 science EXPs come from mechanism diagnosis, not maintenance backlog |
| EXP Quality | Every new EXP answers `What scientific decision changes?` |
| Support Containment | Ordinary support: no new EXP, no Story edit, no full Review; resume the science EXP |
| Method Evolution | Negatives delete a component, change a mechanism, shrink a claim, or reframe — not another parameter grid |

## Reviewer questions (§77)

A framework-only review answers:

1. 是否仍保留科学可靠性？
2. 是否减少工程工作冒充科学 Experiment？
3. Agent 是否更持续地围绕方法假设做实验？
4. 大 ledger 是否不再成为默认上下文？
5. 负结果是否更容易转化为方法修改？
6. 是否新增了不必要状态/Skill/Workflow？
